# Array

## What

数组是一种抽象：把一组同类型的数据组织起来，用索引定位其中的每一个元素。它规定了一组有规则的索引空间，每个合法的索引对应一个元素。

核心不是"连续内存"，也不是"矩阵"，而是：

```
索引 → 元素
一维: i → element
多维: (i₁, i₂, ..., iₙ) → element
```

概括成一句话：**数据集合 + 索引空间 + 定位规则**。

### i. 维度（轴）≠ 索引

**"多维"是访问方式的抽象，不是内存形状。** 多维的意义不是让内存真的变成二维、三维或更高维，而是为具有多个独立索引维度的数据提供一种自然的组织和访问方式——这里"维度"和"索引"两个概念容易混，需要分清：

- **维度/轴（dimension/axis）**：定位一个元素需要多少个独立的索引。`shape=(2,3,4)` 说明有 3 个轴，长度分别是 2、3、4。
- **索引（index）**：某个轴上具体取的值。`a[1][2][3]` 里的 1、2、3 就是这三个轴上的索引。

```
int a[10];        → a[i]        → 1 个轴，1 维
int a[3][4];      → a[i][j]     → 2 个轴，2 维
int a[2][3][4];   → a[i][j][k]  → 3 个轴，3 维
```

N 维同理：`(i₁,...,iₙ) → element`。轴数变多不需要靠几何空间去想象，只是坐标数变多。

## Why

现实中的很多数据，本身就需要多个独立维度来描述其中的一个元素。例如：

- 图像：`(height, width, channel)`
- 视频：`(time, height, width, channel)`
- 实验数据：`(subject, day, temperature, wavelength)`
- 神经网络：`(batch, channel, height, width)`

## How

- 很多语言都提供数组或类似数组的数据结构，但具体语义和实现方式可能不同。每种语言/库可能采用不同的数据布局、stride、间接寻址等方式（比如 NumPy 的 `ndarray` 不是"list 套 list"，而是 `data + shape + strides` 的整体结构）。
- C++ 提供多种表达“数组/连续序列”需求的工具，例如 built-in array、std::array、std::vector。这里暂时只讨论 built-in array。C++ 把数组分为一维和多维，且将多维数组实现为 array of arrays，例如 `int a[2][3][4]` 本质上是数组嵌套数组，这些元素在内存中连续存储。

### i. Operations

在讨论多维数组具体怎么映射到内存之前，先梳理内置数组最基础的语法：怎么声明、怎么初始化、它和指针的关系、它作为函数参数时的种种限制，以及函数如何返回指向数组的指针。

这些规则里贯穿着同一条线索：**数组不支持整体拷贝和赋值；在大多数需要"值"的表达式上下文中，数组会发生 array-to-pointer 退化，但存在 `sizeof`、`&`、`typeid`、`decltype`、引用绑定等明确例外**（具体例外见下面"数组与指针的关系"）。

1. **声明（declaration）**

   一维数组的声明形式是 `基础类型 + 变量名[长度]`，例如 `int a[10]`。

   数组本身也可以是被指向/被引用的对象，这时候要注意运算符优先级——`[]` 的优先级比 `*`/`&` 高，必须用括号把指针/引用符号和变量名括在一起，否则会被解析成"数组的每个元素是指针/引用"：

   ```cpp
   int (*p)[10];      // p 是一个指针，指向一个包含 10 个 int 的数组
   int (&r)[10];      // r 是一个引用，绑定到一个包含 10 个 int 的数组
   int *(&r)[10];     // r 是一个引用，绑定到一个包含 10 个 "int 指针" 的数组
   ```

2. **初始化与赋值**

   - 默认初始化：`int a[10];`（元素值未定义，除非是全局/静态数组）。
   - 显式列表初始化：`int a[] = {1,2,3};`（省略长度时由初始化列表元素个数决定）、`int b[5] = {1,2,3};`（多余元素补 0）。
   - 字符数组可以直接用字符串字面量初始化：`char a[] = "string"`——字符串字面量自带结尾的 `\0`，数组实际长度是字符个数 + 1。
   - **数组不支持整体拷贝和赋值**：不能把一个数组整体初始化或赋值给另一个数组。

3. **数组与指针的关系**

   **数组在大多数表达式上下文中会发生 array-to-pointer conversion，转换结果是指向首元素的指针；在 sizeof、&、typeid、decltype、引用绑定等特定上下文中则保留数组类型**：

   - **`sizeof(arr)`**：拿到整个数组的字节数（`sizeof(T)*N`），而不是一个指针的字节数。
   - **`&arr`**：对整个数组取地址，得到的是"指向数组类型"的指针 `T(*)[N]`，跟 `&arr[0]` 退化后的 `T*` 是两种类型。
   - **`typeid(arr)`**：获得数组本身的运行时类型信息。
   - **`decltype(arr)`**：得到数组本身的类型，不套用表达式里通常会做的退化转换
   - **绑定到引用**：数组绑定给引用时保留原始类型，不管这个引用是局部变量（`int (&r)[9] = a;`）还是函数形参——后面"数组引用形参"（`void print(int (&arr)[10])`）和 `compare` 模板例子，用的正是这条规则。

   ```cpp
   int a[3];
   int *p = a;     // a 被替换成 &a[0]，所以 a == p == &a[0] == &p[0]
   ```

   有了这个指向数组元素的指针之后（不管是退化拿到的，还是 `&a[0]` 手动拿到的），还有两个相关、但并列的知识点：

   1. 这类指针本身支持和 `vector`/`string` 迭代器一样的操作（自增、解引用、比较、做减法得到距离等）
   2. 标准库提供 `std::begin(a)` / `std::end(a)`，可以直接拿到首尾指针，不用自己手写 `a` 和 `a+size`。数组版本的 `std::begin`/`std::end` 通过数组引用模板捕获数组类型和长度 `N`，再返回首元素和尾后位置——引用模板如何靠 `N` 推导长度，见后文"数组作为函数参数"里的推导示例。

   ```cpp
   int *start = std::begin(a);   // 指向第一个元素
   int *last  = std::end(a);     // 指向尾后位置（最后一个元素的下一个位置）
   ```

4. **数组作为函数参数**

   **C++ 标准规定：形参声明为数组类型时，参数类型会被调整为指向其元素类型的指针**, 所以下面三种参数写法声明的其实是同一个函数，参数类型都是 `const int*`，`[10]` 不参与形成实际参数类型：

   ```cpp
   void print(const int*);
   void print(const int[]);
   void print(const int[10]);   // 这里的 10 只是注释性质，编译器不检查
   ```

   这条规则跟"数组不支持整体拷贝和赋值"在设计背景上有关联——内置数组没有普通类对象那样的 value semantics，函数参数也就没有采用"按值复制整个数组"的语义（但这是语言设计角度的理解）。

   但退化成指针也带来一个问题：**函数拿不到数组的原始长度**，必须依赖调用者额外提供信息。常见的三种解决办法：

   1. 哨兵/结束标记——比如 C 风格字符串约定以 `\0` 结尾。
   2. 标准库的 begin/end 约定——调用者传入 `std::begin(arr)` 和 `std::end(arr)` 两个指针。
   3. 显式传一个表示长度的参数。

   如果不想用上面这几种办法管理长度，还有第四种选择——**数组引用形参**，让形参保留数组类型本身（不退化成指针），函数内部就能拿到真实长度：

   ```cpp
   void print(int (&arr)[10]) {
       for (auto elem : arr) cout << elem << endl;
   }
   ```

   代价是这个函数只能匹配长度恰好是 10 的数组，别的长度会编译失败。

   **用模板消除"只能匹配固定长度"的限制**：把长度做成非类型模板参数，让编译器针对每次调用各自推导：

   ```cpp
   template<unsigned N, unsigned M>
   int compare(const char (&p1)[N], const char (&p2)[M]) {
       return strcmp(p1, p2); // 这里传入字符串字面量，因此保证以 '\0' 结尾
   }
   ```

   调用 `compare("hi", "mom")` 时，编译器会分别推出 `N=3`（"hi" 含结尾 `\0`）、`M=4`（"mom" 含结尾 `\0`），因此同一个函数模板可以匹配任意长度的两个字符数组，不再要求两边长度相同或固定为某个值。

   **多维数组作为参数，遵循同一条退化规则**：多维数组的"首元素"是它的下一层（一整行），所以退化成的是"指向这一行的指针"，而不是指向单个元素——这就是为什么除了最外层维度可以省略，其余维度必须显式写出（完整推导见文末 Note）：

   ```cpp
   void print(int (*matrix)[10], int rowSize);   // matrix 是"指向含 10 个 int 的数组"的指针
   void print(int matrix[][10], int rowSize);    // 等价写法
   ```

5. **函数返回指向数组的指针**

   **C++ 规定函数的返回类型不能是数组类型**, 但函数可以返回指向数组的指针或数组引用，也可以返回一个包住数组的类对象（比如 `std::array`，它本身具有普通类对象的值语义，可以按值返回）。

   这是"数组作为函数参数"的另一面：参数讲怎么把数组传进去，这里讲怎么把指向数组的指针传出来。写出"返回指向数组的指针"这个类型有几种写法：

   1. **原始形式**

      ```
      Type (*function(parameter_list))[dimension]
      ```

      ```cpp
      int (*func(int i))[10];   // func 是一个函数，返回指向"含 10 个 int 的数组"的指针
      ```

      这个形式最直观地体现了这个类型该怎么"由内而外"读出来：先看到 `func(int i)`（这是一个函数），外面包一层 `*`（返回的是指针），最外面再包一层 `[10]`（指向的是数组）。写法直观，但嵌套太深，可读性差，实际很少直接这样写。

   2. **先给数组类型起个别名**

      ```cpp
      typedef int arrT[10];   // arrT 是"含 10 个 int 的数组"这个类型的别名
      using arrT = int[10];   // 等价写法（C++11 起）

      arrT* func(int i);      // func 返回一个指向 arrT（即 int[10]）的指针
      ```

      有了别名之后，函数声明就变成普通的"类型* 函数名(参数)"形式，不用再当场拼出数组类型的语法，可读性明显更好——这也是"类型别名"这个语言特性本身最常见的用途之一：把复杂类型包一层，让后续声明变简单。

   3. **尾置返回类型（trailing return type, C++11）**

      ```cpp
      auto func(int i) -> int(*)[10];
      ```

      不引入别名，直接把返回类型挪到函数签名后面、用 `->` 单独写出来，同样避开了原始形式里"函数名被包在类型中间"的问题。

   4. **用 decltype 匹配已有数组的类型**

      如果已经有一个数组，想让函数返回"指向同类型数组"的指针，可以直接借用那个数组的类型：

      ```cpp
      int odd[] = {1,3,5,7,9};
      int even[] = {0,2,4,6,8};
      // returns a pointer to an array of five int elements
      decltype(odd) *arrPtr(int i) {
          return (i % 2) ? &odd : &even;   // returns a pointer to the array
      }
      ```

      这里用到的正是前面"数组与指针的关系"提到的 **decltype 例外**：`decltype(odd)` 推导出的是 `odd` 本身的数组类型（`int[5]`），不会退化成指针，所以 `decltype(odd) *arrPtr(...)` 里的 `*` 是加在数组类型上，结果类型自然就是"指向 int[5] 数组的指针"。

   **四种写法的共同点**：它们表达的是完全相同的类型（"指向某个固定大小数组的指针"），只是语法上把"这是个指针""指向的是数组""数组元素类型/长度是什么"这几块信息用不同的顺序摆放、或者借助别名/推导机制隐藏掉一部分语法噪音，可读性依次变好。

### ii. C++ 内置多维数组：array of arrays

前面 Operations 讲的是数组最基础的语法；这一节具体展开多维数组怎么求值、几种实现方式的取舍、以及怎么落到物理内存上。

1. **内置多维数组索引求值**

   ```cpp
   int a[2][3][4];
   ```

   类型逐层剥离：

   ```
   int[2][3][4] --a[1]--> int[3][4] --[2]--> int[4] --[3]--> int
   ```

   这个"逐级剥离"模型能解释 `a[1][2][3]` 的求值过程，但要注意：这是 C++ 内置数组这一种具体实现的表现，不是"多维数组"这个抽象概念本身的定义。

2. **三种"二维数据"的实现对比**

   | 写法 | 内存布局 | 类型 |
   |---|---|---|
   | `int a[3][4]` | 整块连续 | C 风格内置数组 |
   | `std::array<std::array<int,4>,3>` | 内层元素连续，外层 std::array 元素也连续 | 标准库固定大小容器嵌套（类型安全、值语义） |
   | `std::vector<std::vector<int>>` | 每个内层 `vector` 独立管理自己的连续存储，行间不保证相邻 | 嵌套动态容器 |

   前两者是真正的连续二维数组；后者则是"大维度（行）用指针间接、小维度（列）连续"的模式——每个内层 vector 独立管理自己的连续存储，因此不保证行与行之间连续，访问时也多一层间接跳转。对于需要紧凑二维布局的场景，常见做法是改用一维连续存储并自行计算索引（高性能代码常宁可用一维 `vector<int>` 手动算下标 `a[i*cols+j]`）。

3. **逻辑多维 ↔ 物理线性：stride / layout**

   多维只是逻辑组织方式，底层内存仍然可以是一条线，中间靠 **stride（步长）** 换算：

   > stride：在某个轴上，索引每增加 1，对应的线性内存位置要跳过多少个元素。

   有了每个轴的 stride，offset 公式可以统一写成：

   ```
   offset(i₀, i₁, ..., iₙ₋₁) = i₀·stride₀ + i₁·stride₁ + ... + iₙ₋₁·strideₙ₋₁
   ```

   例如 `shape=(2,3,4)`：`stride = (12, 4, 1)`，即 `offset(i,j,k) = i*12 + j*4 + k*1`——这正是下面 row-major 布局对应的 stride。

   ```
   (i, j) 逻辑坐标 → offset(i,j) = i*cols + j → 物理线性位置
   ```

   C++ 内置多维数组的布局，其实可以从两条已经讲过的语言规则直接推出：① 数组元素连续存储（见后文 Key Points）；② 多维数组是 array of arrays。`int a[3][4]` 可以理解成"3 个 `int[4]`"，这 3 个 `int[4]` 作为外层数组的元素，彼此之间也是连续的，于是最右侧维度天然连续变化——这种布局通常称为 row-major。跟 NumPy 可以用 `order='C'`/`order='F'` 显式选择布局不同，**C++ 内置数组没有"改选 column-major"这个选项**：row-major 是类型结构直接决定的唯一结果，不是一个可配置的默认值。

   **row-major**（NumPy 默认；C/C++ 内置数组只有这一种可能）：最内层（最右边）维度的元素在内存里连续排列——先走完一整行再换行：

   ```
   a[3][4] 的 row-major 布局：
   a[0][0] a[0][1] a[0][2] a[0][3]  a[1][0] ...  (先走完第 0 行)
   ```

   **column-major**（Fortran / MATLAB / Eigen 默认）：反过来，先走完一整列再换列：

   ```
   a[0][0] a[1][0] a[2][0]  a[0][1] ...  (先走完第 0 列)
   ```

   ⚠️ 实战中真会踩的坑：以后接触 Eigen（C++ 矩阵库）、MATLAB，或用 BLAS/LAPACK 传递裸内存时，如果对方默认 column-major 而按 row-major 理解，维度顺序会理解反。

   对于 row-major 的连续三维数组，某一维的 stride 等于其右侧所有维度长度的乘积：`offset(i,j,k) = i*(cols*depth) + j*depth + k`。

## Key Points

**抽象层 / 语言层 / 内存层要分开：**

```
抽象层：      数据集合 + 索引空间 + 定位规则
语言/类型层： C++ 内置数组 = array of arrays
内存/实现层： 内置数组元素连续存储
```

ISO C++ 标准规定数组元素连续分配，多维内置数组作为 array of arrays 因此自然呈 row-major 布局（推导过程见前文）。这保证了 `sizeof(a)==sizeof(T)*N`、`&a[i+1]==&a[i]+1` 这类代码成立。但"连续内存"是实现/存储层面的性质，不是数组抽象本身要求的。

**常见误区：不要用几何空间去想象高维**

把维度理解成"1D=线、2D=面、3D=体"，在 4 维以上会失效、变得抽象难以想象。更可靠的模型是 index-tuple：维度只是"需要几个坐标定位一个元素"，`(i₁,...,iₙ) → element`，100 维也只是"需要 100 个坐标"，没有额外的几何含义。

**一句话总结**：数组不是"线、面、体"，而是"用一个或多个索引组织并定位一组同类型数据"；所谓多维，只是一个元素的位置需要多个坐标共同描述，这些坐标最终需要通过某种布局/定位规则映射到底层数据的位置；stride 是描述这种映射的一种常见方式。

## Note

### i. 多维数组作为参数：一般退化规则是什么

Operations 里提到"多维数组作为参数，只有最外层维度可以省略，其余维度必须显式写出"，这里补充完整推导。

数组退化的本质规则只有一条：**数组用在需要"值"的地方（包括作为函数参数）时，会退化成指向它的元素类型的指针。**

对一维数组 `T a[N]`，元素类型就是 `T`，所以退化成 `T*`。对多维数组 `T a[N1][N2]...[Nk]`，**元素类型不是 `T`，而是去掉最外层维度后剩下的 `T[N2]...[Nk]`**（`a[i]` 取出来的正是这个类型），所以整体退化成：

```
T a[N1][N2]...[Nk]   →   T (*)[N2]...[Nk]
```

只有最外层 N1 从类型里消失，`N2` 到 `Nk` 原样留在指针指向的类型里。原因是：退化只发生一次，把整个数组"打包"成一个指针，而**因为 N2/N3 是指针所指向的“元素类型”的组成部分；为了进行 p+1、p[i] 等操作，编译器必须知道这个元素类型的大小和布局**——`T[N2]...[Nk]` 要成为合法数组类型，`N2` 到 `Nk` 必须全部是编译期已知的具体数字，否则算不出 `sizeof`，也就没法做指针算术（`matrix+1` 要跳过 `N2*...*Nk*sizeof(T)` 字节，全靠这些数字算出来）。N1 之所以能省略，准确说是它根本不出现在退化后的类型里了——退化把它替换成了"指针"本身，写不写、写多少编译器都不关心。

按维度递增验证：

```cpp
T a[N];              // 退化: T*
T a[N1][N2];         // 退化: T (*)[N2]
T a[N1][N2][N3];     // 退化: T (*)[N2][N3]
```

对应到函数参数（每组两种写法等价）：

```cpp
void print(int (*matrix)[10], int rowSize);   // 二维
void print(int matrix[][10], int rowSize);    // 等价写法

void print(int (*cube)[3][4], int size1);     // 三维，最外层可留空
void print(int cube[][3][4], int size1);      // 等价写法
```

一句话记忆：**退化永远只剥最外面那一层，剩下的维度是"指针指向的类型"的一部分，必须完整——这跟一维数组"退化成指向元素的指针"是同一条规则，只是多维数组的"元素"本身恰好还是个数组。**
