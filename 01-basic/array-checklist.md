# Array 理解自测清单

配合 [array.md](./array.md) 和 [array-quiz.md](./array-quiz.md) 使用。三份文件按**同一个顺序**对齐（一~八章）：读 array.md 的一节 → 做这里同一章的自测 → 做题库里同一章的题。

## 怎么用

规则：**先合上 array.md，自己说/推一遍，卡住了再翻笔记对答案。** 每条前面的标签说明这一条怎么测：

- **【背】= 第一档，核心结论**：必须能直接脱稿说出来，不允许现推。答不出来，说明是硬记的内容忘了，直接回去重读。
- **【推】= 第二档，推导起点**：只记起点，结论现场推，不要背结论。答不出来，先确认是"起点"本身忘了，还是起点记得但推不出结论——后者说明要重新走一遍推导，而不是去背结论。
- **【练】= 第三档，语法熟练度和动手验证**：不在这份清单里，在题库里。
- **★ 是重点，共 10 条**；时间不够，只做 ★。

每次自测，给自己分个类，比"答对了几道"更有用：

- **A. 直接记得** / **B. 忘了但看到起点马上能推出来** → 算掌握，跳过
- **C. 起点记得，但推导卡住** → 说明要练的是推导本身，回去重新走一遍过程
- **D. 连起点都忘了** → 回 array.md 对应小节精读

## 一、概念：数组是什么、为什么

> array.md：What / Why / Key Points ｜ 题库：一

- [ ] ★【背】用一句话给数组下定义，**不能出现"连续内存"或"矩阵"这两个词**
- [ ] 【背】"轴 / 轴长 / 维数 / 索引"分别是什么？对 `int a[2][3][4]` 各举出具体的值
- [ ] 【背】为什么数组的随机访问是 O(1)？它和链表、map 的区别在哪？
- [ ] 【背】为什么不能用"线/面/体"这种几何空间去想象高维？更可靠的模型叫什么？
- [ ] ★【背】数组的抽象层、语言/类型层、内存层分别在说什么？为什么这三层不能混为一谈？（**用自己的话说，不是背笔记原句**）
- [ ] 【背】既然有内置数组，为什么还有 `std::array` 和 `vector`？各补了内置数组的什么？

## 二、声明、初始化与赋值

> array.md：How · Operations 1（声明）、2（初始化与赋值） ｜ 题库：二

- [ ] ★【背】`int (*p)[10]`、`int (&r)[10]`、`int *(&r)[10]` 怎么读（由内向外）？为什么必须加括号？为什么没有"引用的数组"？
- [ ] 【背】数组的长度必须是什么？标准 C++ 有变长数组吗？运行期才知道大小时用什么？
- [ ] 【背】内置数组和普通类对象在 value semantics 上有什么重要区别？数组为什么不能整体拷贝/赋值，怎么绕过？（这是"数组不支持整体拷贝赋值"背后的理解模型，笔记里也明确说这是从语言设计角度出发的理解，不是能严格推出来的结论，所以直接记住这个区别本身）

## 三、退化：数组与指针

> array.md：How · Operations 3（数组与指针的关系） ｜ 题库：三

- [ ] ★【背】array-to-pointer 退化发生在什么场合？五个明确的例外是哪五个？
- [ ] 【推】起点：数组在大多数表达式上下文中会发生 array-to-pointer conversion，除非该上下文保留数组类型。
      → 自己想一遍并分别说出理由（不用找一个统一的解释套所有情况，这 5 个例外本来就不是同一种机制）：`sizeof`、`&`、`typeid`、`decltype`、引用绑定，分别为什么保留了数组类型？
- [ ] 【推】起点：指针做算术运算时，"走一步"的大小取决于指针所指对象的类型。
      → 自己推一遍：对 `int a[4]`，`a + 1`、`&a[0] + 1`、`&a + 1` 分别走几个字节？为什么 `&a + 1` 跨得最远（`&a` 的类型是什么）？

## 四、传参与返回

> array.md：How · Operations 4（数组作为函数参数）、5（函数返回指向数组的指针） ｜ 题库：四

- [ ] 【背】C++ 对"数组作为函数参数"和"数组作为函数返回值"分别规定了什么特殊规则？（提示：这两条规则性质不一样，一个是类型调整，一个是硬性禁止——先分清楚是哪个是哪个，再说具体内容）
- [ ] 【背】函数拿不到数组的原始长度时，有哪几种办法？（提示：至少 4 种）
- [ ] ★【推】起点：实参 `arr` 出现在表达式里，已经先退化成了指针。
      → 自己推一遍：为什么形参里的 `int a[10]` 其实只是个指针？`[10]` 为什么不参与参数类型？函数内 `sizeof(a)` 是多少？
- [ ] 【推】起点：保留数组类型（不让它退化）就能保住长度。
      → 自己推一遍：数组引用形参为什么能拿到真实长度？它的代价是什么？模板推导 N（`compare` / `array_size`）怎么消除这个代价？

## 五、多维（一）：类型

> array.md：How · 多维 1（内置多维数组索引求值）、Note 第一部分（多维数组作为参数） ｜ 题库：五

- [ ] ★【推】起点：下标 `a[i]` 的定义是 `*(a+i)`；多维数组是 array of arrays。
      → 自己推一遍：对 `int a[3][4]`，`a[0]` 的类型是什么？为什么 `int* q = a[0];` 合法，而 `int* q = a;` 不合法？
- [ ] ★【推】起点：数组退化只发生一次，得到的是"指向数组元素类型的指针"；对多维数组，内层维度是这个元素类型的一部分，要对这个指针做指针算术（`p+1`、`p[i]`）和下标访问，就需要知道这些内层维度的具体大小。
      → 自己推一遍：`T a[N1][N2][N3]` 作为函数参数退化成什么类型？为什么只有 `N1` 能省略，`N2`、`N3` 不能？
- [ ] 【推】起点：指针的"走一步"取决于所指的类型，而指针值里只有地址。
      → 自己推一遍：对 `int a[3][4]`，`a + 1`、`a[0] + 1`、`&a + 1` 分别向后移动多大？为什么起点相同、步长不同？
- [ ] 【推】起点：多维数组是 array of arrays，逐层剥离，每剥一层就少一个维度。
      → 不查资料推一遍：对 `int a[3][4]`（设 `sizeof(int)==4`），`sizeof(a)`、`sizeof(a[0])`、`sizeof(a[0][0])` 分别是多少？

## 六、多维（二）：布局

> array.md：How · 多维 2（三种"二维数据"的实现对比）、3（stride / layout） ｜ 题库：六

- [ ] 【背】`int a[3][4]`、`std::array<std::array<int,4>,3>`、`vector<vector<int>>` 三种"二维数据"：大小何时确定、存在哪里、是否整块连续？
- [ ] 【背】stride 是什么？对 `shape=(2,3,4)` 的 row-major 数组，stride 和 offset 公式分别是什么？
- [ ] ★【推】起点：① 数组元素连续存储　② 多维数组是 array of arrays。
      → 自己推一遍：为什么 `int a[3][4]` 一定是 row-major，C++ 内置数组能不能改成 column-major？哪些库默认 column-major，混用时会踩什么坑？

## 七、因果链：为什么是这样

> array.md：Note 第二部分 ｜ 题库：七

- [ ] ★【背】用"于是"把数组退化的因果链说出来：为了让结构体里的数组就是那几个字节 → 取消"指针格子" → 数组名 / 形参 / `a[i]` 各变成什么 → 指针类型必须带步长（留内层维度、丢最外层数量）→ 类型能保证什么、保证不了什么。（**用自己的话，不是背笔记原句**）
- [ ] 【背】"取消格子"省了什么？它是"时间换空间"吗？（用一句话说清"把什么换成了什么"）
- [ ] 【推】起点：C 取消了数组里的"指针格子"——数组对象就是元素本身，指针只在表达式里现算出来。
      → 自己推一遍：数组名为什么不能赋值？下标 `a[i]` 的定义为什么是 `*(a+i)`？`int a[10]` 和 `int* p = new int[10]` 差在哪？
- [ ] 【推】起点：退化保留了寻址必需的信息（元素类型，含内层维度），丢掉了数量。
      → 自己推一遍：类型能保证什么、保证不了什么？想把数量留住，有哪几种写法？（提示：数组引用、`&a`、模板推导）

## 复习节奏建议

- 不用每次都从头到尾过一遍，随机抽 3~5 条自测即可，几分钟搞定；时间紧就只做 ★。
- 建议间隔：第 1、3、7、14、30 天各来一遍。第 30 天那次不用逐条来，合上笔记，花 3~5 分钟从头到尾口述一遍"Array 是什么 → 多维是什么 → array of arrays → 退化（含它的来由：结构体里的数组 → 取消指针格子）→ 多维参数 → 连续布局"，能完整讲下来就算过关，以后主要靠实际代码触发回忆。
- 如果哪一条连续两次都是 C/D，说明要单独回 array.md 里对应小节精读一次，而不是继续泛泛重复。
- 真正在 STC/TC+ 代码里碰到数组形参、多维数组写法时，顺手用【背】【推】这两档内容解释一下"为什么这么写"——比任何形式的笔记复习都记得牢。
