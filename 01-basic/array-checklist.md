# Array 理解自测清单

配合 [array.md](./array.md) 使用。规则：**先合上 array.md，自己说/推一遍，卡住了再翻笔记对答案**。第一档答不出来说明是硬记的内容忘了，直接回去重读；第二档答不出来，先确认是"起点"本身忘了，还是起点记得但推不出结论——后者说明要重新走一遍推导，而不是去背结论。

每次自测，给自己分个类，比"答对了几道"更有用：

- **A. 直接记得** / **B. 忘了但看到起点马上能推出来** → 算掌握，跳过
- **C. 起点记得，但推导卡住** → 说明要练的是推导本身，回去重新走一遍过程
- **D. 连起点都忘了** → 回 array.md 对应小节精读

## 第一档：核心结论（必须能直接脱稿说出来，不允许现推）

- [ ] 用一句话给数组下定义，**不能出现"连续内存"或"矩阵"这两个词**
- [ ] "维度/轴"和"索引"的区别是什么？各举一个例子
- [ ] 为什么不能用"线/面/体"这种几何空间去想象高维？更可靠的模型叫什么？
- [ ] 数组的抽象层、语言/类型层、内存层分别在说什么？为什么这三层不能混为一谈？（**用自己的话说，不是背笔记原句**）
- [ ] 内置数组和普通类对象在 value semantics 上有什么重要区别？（这是"数组不支持整体拷贝赋值"背后的理解模型，笔记里也明确说这是"语言设计角度的理解"，不是能严格推出来的结论，所以直接记住这个区别本身）
- [ ] C++ 对"数组作为函数参数"和"数组作为函数返回值"分别规定了什么特殊规则？（提示：这两条规则性质不一样，一个是类型调整，一个是硬性禁止——先分清楚是哪个是哪个，再说具体内容）

## 第二档：推导起点（只记起点，结论现场推，不要背结论）

- [ ] 起点：① 数组元素连续存储　② 多维数组是 array of arrays。
      → 自己推一遍：为什么 `int a[3][4]` 一定是 row-major，C++ 内置数组能不能改成 column-major？
- [ ] 起点：数组在大多数表达式上下文中会发生 array-to-pointer conversion，除非该上下文保留数组类型。
      → 自己想一遍并分别说出理由（不用找一个统一的解释套所有情况，这 5 个例外本来就不是同一种机制）：`sizeof`、`&`、`typeid`、`decltype`、引用绑定，分别为什么保留了数组类型？
- [ ] 起点：数组退化只发生一次，得到的是"指向数组元素类型的指针"；对多维数组，内层维度是这个元素类型的一部分，要对这个指针做指针算术（`p+1`、`p[i]`）和下标访问，就需要知道这些内层维度的具体大小。
      → 自己推一遍：`T a[N1][N2][N3]` 作为函数参数退化成什么类型？为什么只有 `N1` 能省略，`N2`、`N3` 不能？
- [ ] 起点：函数拿到的是退化后的指针，丢失了数组原始长度。
      → 自己列一遍：笔记里提到了哪几种让函数知道数组长度的办法？（提示：至少 4 种）
- [ ] 起点：多维数组的"首元素"是它去掉最外层维度后剩下的类型（这个类型本身还是个数组）。
      → 自己推一遍：为什么多维数组作为参数时，退化成的是"指向一整行的指针"，而不是"指向单个元素的指针"？
- [ ] 起点：指针做算术运算时，"走一步"的大小取决于指针指向的元素类型。
      → 自己推一遍：对 `int a[3][4]`，`a + 1` 和 `a[0] + 1` 分别向后移动多大？为什么两者不一样大（`a` 和 `a[0]` 退化后是不同的指针类型）？
- [ ] 起点：多维数组是 array of arrays，逐层剥离，每剥一层就少一个维度。
      → 不查资料推一遍：对 `int a[3][4]`（设 `sizeof(int)==4`），`sizeof(a)`、`sizeof(a[0])`、`sizeof(a[0][0])` 分别是多少？

## 复习节奏建议

- 不用每次都从头到尾过一遍，随机抽 3~5 条自测即可，几分钟搞定。
- 建议间隔：第 1、3、7、14、30 天各来一遍。第 30 天那次不用逐条来，合上笔记，花 3~5 分钟从头到尾口述一遍"Array 是什么 → 多维是什么 → array of arrays → 退化 → 多维参数 → 连续布局"，能完整讲下来就算过关，以后主要靠实际代码触发回忆。
- 如果哪一条连续两次都是 C/D，说明要单独回 array.md 里对应小节精读一次，而不是继续泛泛重复。
- 真正在 STC/TC+ 代码里碰到数组形参、多维数组写法时，顺手用这两档内容解释一下"为什么这么写"——比任何形式的笔记复习都记得牢。
