# Initialization Basics

> 范围：初始化与赋值的区别，初始化涉及的几个相邻概念，初始化的形式与主要种类，以及它们之间的关系。拷贝、直接、列表初始化，窄化转换和聚合初始化的详细规则见 [02-initialization-forms.md](02-initialization-forms.md)。静态、动态初始化及程序启动过程见 [03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md)。类对象的构造过程（含 `explicit`）见 [constructors-and-destructors.md](../../02-class-and-oop/constructors-and-destructors.md)。条文号以 C++20（N4861）为基线，现行草案不同之处另注。

## 1. 核心概念

### 1.1 初始化与赋值

- **初始化**（initialization）：对象或引用创建时，根据初始化写法、类型和语境适用的规则建立初始状态。初始化不等于调用构造函数，也不一定会产生确定的初始值（如默认初始化的 int x;）。对于通过构造函数初始化的类对象，初始化过程包括基类和非静态数据成员子对象的初始化，以及构造函数体的执行；这些子对象在构造函数体执行前完成初始化，整个对象的初始化在非委托构造函数返回时完成（CWG 2756）。
- **赋值**（assignment）：对生命周期已经开始的对象，通过赋值操作改变其值或状态

### 1.2 与其他概念的关系

理解初始化，还需要区分下面四个概念。每条只是一句话定义，完整规则见各自的笔记：

- **作用域**（scope）：名字在其中有效的那部分程序文本，决定名字查找的范围。详见 [scope.md](../../../07-language-mechanics/scope.md)。
- **链接**（linkage）：名字的性质，决定别的作用域里的名字能不能指代同一个实体。详见 [storage-class-specifiers-and-linkage.md](../../../07-language-mechanics/storage-class-specifiers-and-linkage.md) 的 Linkage 一节。
- **存储期**（storage duration）：对象所占存储的最短潜在存活期，由创建对象的构造决定，分静态、线程、自动、动态四种。详见 [storage-duration.md](../storage-duration.md)。
- **生命周期**（lifetime）：对象和引用的运行期性质。对象的生命周期在获得合适的存储、且初始化（若有）完成时开始；在对象被销毁、存储被释放或被复用等情况下结束。详见 [lifetime.md](../lifetime.md)。

它们属于不同维度，不能互相替代：作用域和链接描述名字；存储期描述存储；生命周期描述对象或引用；初始化和赋值是改变对象状态的两种操作。存储期约束生命周期.

```text
获得存储 → 初始化 → 初始化完成（生命周期开始）→ 使用、赋值 → 生命周期结束 → 存储释放
```

## 2. 初始化的分类与判定

### 2.1 分类思路

判断一次初始化，要分清三件事：

- **形式**（form）：写法和场合。写法是有没有初始化器，写成 `()`、`(args)`、`= expr`、`{args}` 还是 `= {args}`；场合是变量定义、按值传参、按值返回、抛出和处理异常、聚合成员等。
- **种类**（kind）：标准给初始化规则起的名字：默认、值、零、拷贝、直接、列表、聚合初始化。
- **行为**：这条规则落到这个对象上具体做什么：选哪个构造函数、做哪种转换、初始化哪些元素。

**形式是入口，种类是规则，行为是结果。** 形式先定下首先适用的种类；种类再由目标类型和初始化器定出行为；行为常常又交给另一种种类。标准的判定顺序在 C++20 [dcl.init]/12 和 /17（现行草案 [dcl.init.general]/11 和 /15）。所以七个种类不是并列的七格：

- 默认、值、拷贝、直接、列表初始化都有对应的写法；值初始化也会被列表初始化和聚合的缺省元素带出（见下）。
- 直接列表和拷贝列表是列表初始化在两种语境里的形式：花括号写法有列表初始化自己的规则（窄化、initializer-list 优先），同时按语境属于直接初始化或拷贝初始化。
- 零初始化没有写法，由别的规则触发（2.2）；聚合初始化由列表初始化在 T 是聚合时选中，C++20 起圆括号写法也可以。

| 写法与场合 | 种类 | 示例 | 行为（由类型和初始化器决定） |
|---|---|---|---|
| 不写初始化器 | 默认初始化 | `T x;`、`new T` | 类：默认构造函数；数组：逐元素；其他：什么也不做 |
| 空圆括号 `()` | 值初始化 | `T()`、`new T()`、成员初始化器 `m()` | 类：看默认构造函数是不是 user-provided；数组：逐元素；其他：零初始化 |
| `= 表达式`；按值传参、按值返回、抛出和处理异常 | 拷贝初始化 | `T x = expr;`、`f(a)`、`return a;` | 类：同类纯右值，它的结果对象就是目标对象，不查构造函数（C++17）；同类或派生类的源，只考虑转换构造函数；其他源类型，找用户定义转换。非类：标准转换（源是类类型时先用它的转换函数） |
| 圆括号表达式列表 | 直接初始化 | `T x(a)`、`new T(a)`、`T(a)`、成员初始化器 `m(a)` | 类：全部构造函数参加重载决议（C++20 起聚合可逐元素初始化）。非类：标准转换（源是类类型时先用它的转换函数） |
| 花括号列表，不带 `=` | 直接列表初始化 | `T x{a}`、`new T{a}`、`T{a}` | 聚合：通常做聚合初始化；非聚合类：空列表且有默认构造函数时值初始化，否则 initializer-list 构造函数优先、再看全部构造函数；非类：单元素直接初始化，空列表值初始化；禁止窄化 |
| `= { … }`、`f({ … })`、`return { … };` | 拷贝列表初始化 | `T x = {a};` | 同上，但非类的单元素按拷贝初始化；选中 `explicit` 构造函数则 ill-formed |

注意：变量声明 `T x();` 会被解析为函数声明，不是值初始化；空 `()` 只能出现在 `new T()`、函数式转换 `T()`、成员初始化器 `m()` 里（[dcl.init]/11 的注）。

**种类之间的委托**，也就是行为落在哪里：

- 值初始化 → 零初始化，再默认初始化（看默认构造函数是不是 user-provided，2.2）。
- 列表初始化 → 聚合初始化（T 是聚合）；值初始化（空列表）；构造函数的两步选择（其他类）；直接或拷贝初始化（非类的单个元素）。
- 聚合初始化 → 每个元素拷贝初始化（元素本身是花括号列表时再列表初始化）；没给子句的元素：用默认成员初始化器，没有的话，花括号形式从空列表拷贝初始化（通常进一步值初始化）。
- 拷贝初始化（源类型无关的类）→ 用户定义转换，结果再直接初始化目标。
- 直接初始化（C++20，圆括号）→ 没有可行构造函数的聚合，做聚合初始化。

```cpp
struct A { int x; int y; };
A a{1, 2};    // 列表初始化 → 聚合初始化：x、y 由子句拷贝初始化
A b{};        // 列表初始化 → 聚合初始化 → 元素从 {} 拷贝初始化 → 值初始化 → 零初始化
int c{};      // 列表初始化 → 空列表 → 值初始化 → 零初始化
int d = 0;    // 拷贝初始化：标准转换，不经过零初始化
```

同一种写法，类型不同，结果可以不同。下面几个分叉点会产生可观察的差异（g++ 11.4、clang 14，C++11–20 实测）：

| 分叉点 | 例子 | 结果 | 详见 |
|---|---|---|---|
| 空花括号：聚合与非聚合 | `A a{};`、`B b{};`（A 是聚合，B 是有默认构造函数的非聚合） | `a` 聚合初始化；`b` 值初始化，调用 `B()` | 2.2 |
| initializer-list 构造函数优先 | `std::vector<int> v{3, 5};`、`std::vector<int> w(3, 5);` | `v` 有 2 个元素；`w` 有 3 个元素，值都是 5 | forms How ii.3 |
| 窄化转换 | `int x{3.14};`、`int y(3.14);`、`int z = 3.14;` | 第一句编译错误，后两句通过 | forms What、How ii.3 |
| `explicit` 构造函数 | `E e = 1;`、`E e(1);`（`explicit E(int)`） | 第一句编译错误，第二句通过 | constructors-and-destructors.md §5 |

这里的 forms 指 [02-initialization-forms.md](02-initialization-forms.md)：What 一节有总表，How 的 i 讲拷贝与直接初始化，ii 讲列表初始化（含聚合），iii 讲 `initializer_list` 的底层数组；`explicit` 的规则在 [constructors-and-destructors.md](../../02-class-and-oop/constructors-and-destructors.md) §5。

### 2.2 默认初始化、值初始化与零初始化

这三种初始化经常组合出现，是理解对象初始状态的基础。

#### 默认初始化（default-initialization）

**发生条件**：对象没有提供初始化器，如 `T x;`、`new T`（[dcl.init]/12）；构造函数里没出现在成员初始化列表、也没有默认成员初始化器的基类和非静态数据成员，也按默认初始化（[class.base.init]/9）。

**行为**取决于类型（[dcl.init]/7）：

- 类类型：调用重载决议选出的默认构造函数。
- 数组：逐元素默认初始化。
- 其他类型：不执行初始化。

因此，自动或动态存储期的 `int` 没有获得初始值，不能读取。静态或线程存储期的变量，只要没做常量初始化，就先被零初始化（[basic.start.static]/2），所以全局的 `int g;` 是 0。引用不能默认初始化；`const` 对象只有 T 是 const-default-constructible 时才能默认初始化（[dcl.init]/7，如 `const std::string s;` 可以，`const int x;` 不行）。

#### 值初始化（value-initialization）

**发生条件**：初始化器是空圆括号或空花括号：`T()`、`new T()`、`T{}`、`T x{}`、成员初始化器 `m()` 和 `m{}`（[dcl.init]/17，[dcl.init.list]/3）。但 T 是聚合时，`T x{}` 做聚合初始化，不是值初始化；T 是有默认构造函数的非聚合类、或标量，才是值初始化。标准容器按个数构造、或 `resize` 增长时，新元素也是值初始化的（cppreference；分配器定制了 `construct` 的除外）。

**行为**取决于类型（C++20 [dcl.init]/8）：

- 标量：零初始化。
- 数组：逐元素值初始化。
- 类类型：看默认构造函数：
  - 不是 user-provided（也没被删除）：先把整个对象零初始化，再默认初始化。C++20 原文把后一步限定为“默认构造函数不平凡时”，现行草案改成一律默认初始化；平凡的默认构造函数什么也不做，效果相同。
  - 是 user-provided：只调用它（默认初始化），它没碰的成员不会被清零。
  - 被删除或不存在：ill-formed。标准的措辞是“按默认初始化处理”，而默认初始化在这两种情形下不能成立。

user-provided 指用户声明、且没有在**首次声明**时就写成 `= default` 或 `= delete` 的函数（[dcl.fct.def.default]/5）。所以隐式生成的、类内首次声明就写 `= default` 的都不算；类内只声明、类外才写 `T::T() = default;` 的算。

```cpp
struct P { int x; };           // 默认构造函数是隐式生成的，不是 user-provided
struct U { int x; U() {} };    // 默认构造函数是 user-provided，没碰 x

int g;                         // 静态存储期：先零初始化；默认初始化对 int 什么也不做 → 0
U gu;                          // 先零初始化，再调用 U()；U() 没碰 x → x 仍是 0

int main() {
    int* a = new int();        // 值初始化 → 0
    P*   b = new P();          // 值初始化：P 的默认构造函数不是 user-provided，先清零 → 0
    int* c = new int;          // 默认初始化 → 值不确定，不能读
    U*   d = new U();          // 值初始化：U() 是 user-provided，只调用它 → x 值不确定，不能读
}
```

标准保证 `g`、`gu.x`、`*a`、`b->x` 都是 0（g++ 11.4 和 clang 14，`-std=c++11` 与 `-std=c++20` 下实测都打印 0）；`*c` 和 `d->x` 不能读。

容易混淆的地方：`T()` 并不总比不写初始化器多一次清零。默认构造函数是 user-provided 时，两者没有区别，都只调用它（例子里的 `U`）；数组则逐元素进行：`new int[3]()` 的每个元素是值初始化，都是 0，`new int[3]` 的每个元素是默认初始化，值不确定。

#### 零初始化（zero-initialization）

零初始化没有独立的写法，由别的规则触发：

- 静态或线程存储期的变量，没做常量初始化时，先于其他初始化进行（C++20 [basic.start.static]/2）。
- 作为值初始化的一部分：标量，以及默认构造函数不是 user-provided 的类。
- 字符数组用较短的字符串字面量初始化时，剩下的元素补零（[dcl.init.string]/3）。

结果取决于类型（C++20 [dcl.init]/6）：标量得到由整数 0 转换来的值；非联合类：填充位置零，每个非静态数据成员、基类子对象逐个零初始化；联合体：填充位置零，第一个具名非静态数据成员零初始化；数组：逐元素；引用：什么也不做。

因此，全局 `int g;` 的 0 来自静态初始化阶段的零初始化，不是默认初始化给的。静态初始化与动态初始化的关系见 [03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md) §2.2。

### 2.3 其他主要初始化种类

下面四种与具体写法和类型密切相关，详细规则统一放在 [02-initialization-forms.md](02-initialization-forms.md)，这里只给定义和定位：

| 种类 | 定义和发生场合 | 作用 |
|---|---|---|
| 拷贝初始化（copy-initialization，[dcl.init]/15） | `=` 形式、按值传实参、按值返回、抛出和处理异常、聚合成员的初始化 | 是隐式转换的语境（[conv]/3），所以 `explicit` 构造函数不参加；不意味着一定调用拷贝构造函数 |
| 直接初始化（direct-initialization，[dcl.init]/16） | 初始化器是圆括号表达式列表或花括号列表；`new`、`static_cast`、函数式转换；成员初始化器 | 圆括号形式：把表达式列表当作实参，在类的全部构造函数里做重载决议；花括号形式（直接列表初始化）：按列表初始化的两步选择。两者的 `explicit` 构造函数都可以参加 |
| 直接列表初始化（direct-list-initialization，[dcl.init.list]/1，语境见 [dcl.init]/16） | 花括号初始化列表出现在直接初始化的语境里：`T x{a}`、`T{a}`、`new T{a}`、成员初始化器 `: m{a}`、不带 `=` 的默认成员初始化器 `T m{a};`、condition 里的 `if (T x{a})` | 按 [dcl.init.list]/3 分流：聚合走聚合初始化，空列表（类需有默认构造函数）走值初始化，其他类先试 initializer-list 构造函数、再看全部构造函数；禁止窄化转换。`explicit` 构造函数可以被选中；非类的单个元素按直接初始化（`explicit` 转换函数可用）；固定底层类型的枚举可由单个整数初始化（C++17） |
| 拷贝列表初始化（copy-list-initialization，[dcl.init.list]/1，语境见 [dcl.init]/15） | 花括号初始化列表出现在拷贝初始化的语境里：`T x = {a}`、`return {a};`、函数/运算符/构造函数调用的实参 f({a})、v[{a}]、x = {a}、U({a}), 带 `=` 的默认成员初始化器 `T m = {a};` | 分流规则和窄化限制与直接列表初始化相同。区别：选中 `explicit` 构造函数则 ill-formed（不会改选）；非类的单个元素按拷贝初始化（`explicit` 转换函数不参加）；固定底层类型的枚举不能这样初始化 |

引用初始化和字符数组的字符串字面量初始化有各自的规则（[dcl.init.ref]、[dcl.init.string]），本篇不展开。

不要混淆初始化种类与初始化阶段：默认、值、零、拷贝、直接、列表、聚合初始化描述对象如何被初始化；常量初始化和零初始化合称静态初始化，是静态、线程存储期变量初始化过程中的阶段划分。两者不是同一套分类：零初始化两边都出现，它既是一种初始化操作（2.2），也是静态初始化阶段的一部分。见 [03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md) §2.2。
