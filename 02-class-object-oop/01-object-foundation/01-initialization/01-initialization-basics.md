# Initialization Basics

## 1. some explains

- **初始化**（Initialization）描述对象如何获得初始状态，比构造函数调用的范围更广：用哪种初始化规则，由初始化的写法、被初始化对象的类型和所处的上下文决定；初始化不一定调用构造函数，也不一定给对象一个确定的值（如默认初始化 `int x;`）。通过构造函数初始化的类类型对象，初始化还包括初始化基类和成员子对象、执行构造函数体：基类和非静态数据成员子对象在构造函数体执行前完成初始化，整个对象的初始化在非委托构造函数返回时完成（CWG 2756，见 §3.2）。初始化的各种写法和种类（默认、值、零、拷贝、直接、列表、聚合）见本篇 §3.1 和 [02-initialization-forms.md](02-initialization-forms.md)。
- **赋值**（Assignment）是对已经存在的对象，用新的值替换它当前的值（C++20 [expr.ass]/2）。
- **生命周期**（Lifetime）是对象（和引用）的运行期性质：从获得存储、且初始化（如果有；包括 vacuous initialization）完成时开始，到析构函数调用开始（非类类型是对象被销毁）、或存储被释放或复用时结束。这里只是概括，完整规则和 vacuous initialization 的定义见 [lifetime.md](../lifetime.md)。
- **作用域**（Scope）是程序文本里的一个区域，名字查找以它为单位，声明引入的名字在其中生效。它是语言的静态规则（编译期决定），与对象何时存在无关；也不等于“名字此刻看得见”：内层的同名声明会遮住外层的名字。完整说法见 [scope.md](../../../07-language-mechanics/scope.md)（那里的术语是 C++23 起的写法）。
- **存储期**（Storage duration）是对象所占存储的最短潜在存活期，由创建对象的构造决定，分静态、线程、自动、动态四种。

## 2. relations

- 时间顺序（正常销毁的路径）：获得存储 → 初始化完成（生命周期开始）→ 析构函数调用开始（生命周期结束）→ 释放存储。生命周期也可以不经析构函数而结束：存储被释放，或被一个不嵌套在它里面的对象复用（[lifetime.md](../lifetime.md)）。对象的生命周期等于或嵌套在其存储的存活期之内。
- 作用域、生命周期、存储期是三个不同的概念，不能互相替代：作用域是名字（声明）的编译期性质，生命周期是对象的运行期性质，存储期是对象所占存储的最短潜在存活期，由创建方式决定。它们有关联（对象的生命周期总在其存储的存活期之内），但起止点不同，下面三条是例子。
  - 名字在作用域内，对象不一定活着：`int x = sizeof(x);` 里，`x` 在自己的初始化器中已经能被名字查找找到（声明点在声明符之后、初始化器之前，见 [scope.md](../../../07-language-mechanics/scope.md) ③），此时初始化还没完成、生命周期还没开始；`sizeof` 不求值，所以这句合法（换成 `int x = x;` 就是读一个还没初始化的 `x`，g++、clang 在 `-Wall` 下都会警告，实测）。悬空引用的名字还在，被引用的对象已经结束。
  - 对象活着，名字不一定看得见：`new` 出来的对象没有名字；外层的名字被内层同名声明遮住。
  - 静态存储期的变量，存储在整个程序期间都在，生命周期却从初始化完成才开始：需要动态初始化的函数内 `static` 变量，要到第一次执行到声明处才构造（C++20 [stmt.dcl]/4）；零初始化和常量初始化属于静态初始化，不受这条限制，见 [03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md) §2.4。实测：先打印 main 开头，第一次调用才构造，main 结束后才析构；`nm` 里它在 `.bss`，旁边多一个 guard variable 记录"是否已初始化"。
- 初始化建立对象的初始状态，不一定是一个确定的值（`int x;` 默认初始化什么也不做，值不确定）；赋值是给生命周期已开始的对象换值。

## 3. some concepts

### 1) 默认、值、零：各做什么

| 种类 | 什么时候发生 | 做什么（按被初始化对象的类型 T） |
|---|---|---|
| 默认初始化 | 没写初始化器 | 类类型：调用选中的默认构造函数；数组：逐元素默认初始化；其他类型：**什么也不做** |
| 值初始化 | 初始化器是 `()`；花括号为空时：T 是聚合走聚合初始化，T 是有默认构造函数的非聚合类或标量才走值初始化 | 标量：零初始化；类类型：见下；数组：逐元素值初始化 |
| 零初始化 | 没有对应的写法，由别的初始化触发 | 标量：变成 0；类类型：每个非静态成员、基类子对象逐个零初始化，填充位置零；联合体：第一个具名成员；数组：逐元素；引用：什么也不做 |

类类型的值初始化，看默认构造函数是不是 user-provided。user-provided 的定义（[dcl.fct.def.default]/5）：用户声明的函数，且没有在**首次声明**时就写成 `= default` 或 `= delete`。所以隐式生成的、类内首次声明就写 `= default` 的都不算；类内只声明、类外才写 `T::T() = default;` 的算：

- 不是 user-provided（也没被删除）：先把整个对象零初始化，再（若默认构造函数不是平凡的）默认初始化。
- 是 user-provided、被删除、或根本没有默认构造函数：只做默认初始化。所以用户的构造函数没碰的成员不会被清零；没有默认构造函数或它被删除时，编译不过。

三者的关系：

- 值初始化是用另外两种拼出来的：标量直接零初始化；类类型按上面两条，默认构造函数不是 user-provided 时零初始化再加默认初始化，是 user-provided 时只做默认初始化。所以 `T()` 比不写初始化器多"清零"这一步，只对标量和默认构造函数不是 user-provided 的类成立；数组逐元素进行（`new int[3]()` 的每个元素是值初始化，都是 0；`new int[3]` 的每个元素是默认初始化，值不确定）；默认构造函数是 user-provided 时两者没有区别，都只调用它（下面例子里的 `U`）。
- 零初始化自己没有写法，主要在两处被用到：值初始化，以及静态/线程存储期变量没做常量初始化时（[03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md) §2.3）。
- 默认初始化对标量什么也不做，所以局部的 `int x;` 值不确定；全局的 `int g;` 是 0，靠的是零初始化。

```cpp
struct P { int x; };           // 默认构造函数是隐式生成的，不是 user-provided
struct U { int x; U() {} };    // 默认构造函数是 user-provided，没碰 x

int g;                         // 静态存储期：先零初始化；默认初始化对 int 什么也不做 → 0
U gu;                          // 先零初始化，再调用 U()；U() 没碰 x → x 仍是 0

int main() {
    int* a = new int();        // 值初始化 → 0
    P*   b = new P();          // 值初始化：P 的默认构造函数不是 user-provided，先清零 → 0
    int* c = new int;          // 默认初始化 → 值不确定，不能读
    U*   d = new U();          // 值初始化：U() 是 user-provided，只调用它 → x 值不确定，不能读
}
```

标准保证 `g`、`gu.x`、`*a`、`b->x` 都是 0（g++ 11.4 和 clang 14，`-std=c++11` 与 `-std=c++20` 下实测都打印 0）；`*c` 和 `d->x` 不能读。

### 2) 类对象的初始化：构造函数与成员初始化列表

- **构造函数**：非聚合类类型对象的初始化通常通过构造函数完成；聚合类走聚合初始化，按聚合元素（成员，C++17 起还有基类）的顺序逐个初始化，不调用该聚合类自身的构造函数（如 `struct P { int a; int b; }; P p{1, 2};`）。类类型的元素或成员子对象，自己的初始化仍会调用它们的构造函数：`struct Member { Member(int); }; struct A { Member m; }; A a{10};` 里，`a` 走聚合初始化，`m` 由 `10` 初始化，调用的是 `Member(int)`（g++ 11.4、clang 14 实测）。调用哪一个构造函数，由初始化的写法（如默认、直接、拷贝、列表初始化）按重载决议决定；构造函数调用不是另一种初始化类别。
- **默认成员初始化器**（C++11）：只用于非静态数据成员（C++20 [class.mem]/10，现行草案 [class.mem.general]/15），在成员声明处给初值，`int z = 30;` 或 `int z{30};`。不能写圆括号：`int z(30);` 会被当成函数声明而报错（实测）。静态数据成员的类内初始化是另一回事，见 [static-data-members.md](../../02-class-and-oop/static-data-members.md)。
- **成员初始化列表**（非委托构造函数）：在构造函数体执行之前，指定每个基类和非静态成员怎么初始化。
  - 没写的成员：有默认成员初始化器就用它，否则默认初始化（内置类型什么也不做；联合体和匿名联合的变体成员则完全不初始化，[class.base.init]/9）。
  - 写了的成员：它的默认成员初始化器被忽略。
  - 默认初始化行不通的，必须在列表里写（或改用默认成员初始化器）：引用成员、内置类型的 `const` 成员、没有默认构造函数的成员和基类。类类型的 `const` 成员要看它能不能默认初始化，`const std::string s;` 这样的成员可以不写（实测）。
  - 不在列表里写、改在函数体里赋值，是先默认初始化再赋值，两步；列表里写 `m(1)` 一步完成（前提：该成员能默认初始化，赋值也合法；引用成员和内置类型的 `const` 成员做不到，见上一条）。
  - 写法决定形式：`x(n)` 是直接初始化，`x{n}` 是直接列表初始化，不允许窄化转换（clang 报错，g++ 只警告）。
- **委托构造函数**（C++11）：mem-initializer 里写本类名，并且只能单独出现（再写别的成员初始化会报错，实测）；先执行目标构造函数，它返回后才执行委托者的函数体。对象的初始化在目标（非委托）构造函数返回时就算完成（§1 提到的 CWG 2756；C++20 原文只写了"目标构造函数返回后才执行委托者的函数体"），所以委托者的函数体抛异常时，析构函数会被调用；非委托构造函数的函数体抛异常则不会（g++ 11.4、clang 14 实测一致）。
- **初始化顺序只看声明，不看列表的书写顺序**：虚基类（只由最派生类初始化，按基类图的深度优先、从左到右）→ 直接基类（按基类列表的顺序）→ 非静态成员（按类里的声明顺序）→ 构造函数体。析构时先执行析构函数体，再按初始化的相反顺序销毁成员和基类子对象（C++20 [class.dtor]/14，现行草案 /13）。标准这样规定，就是为了让销毁顺序恰好是初始化顺序的逆序。所以一个成员依赖另一个成员时，被依赖的要先声明；写反了编译器会警告（g++：`-Wreorder`）。

```cpp
struct A {
    int x;
    const int y;                       // const int 成员：必须在列表里初始化
    int z = 30;                        // 默认成员初始化器
    A(int n) : z(n), y(20), x(10) {}   // 书写顺序 z、y、x；实际顺序 x、y、z，然后函数体；z 的默认值被忽略
};
```

- 验证：[lifetime-and-initialization-exp.cpp](../../lifetime-and-initialization-exp.cpp) 实验 1（顺序，故意触发 `-Wreorder`）。标准：[class.base.init]/6（委托）、/9、/10、/13（C++20）。
- 关联：全局对象的构造函数是 `constexpr`、且整个初始化是常量表达式时，做常量初始化，不必在运行时调用构造函数，见 [03-static-initialization-and-program-startup.md](03-static-initialization-and-program-startup.md) §2.2 表里的 `gc` 一行和 §2.3。
